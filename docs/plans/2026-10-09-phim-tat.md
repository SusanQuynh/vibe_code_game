# Starlight Ent. — Kế hoạch phím tắt bàn phím

> **Cho người thực thi:** làm tuần tự từng task, mỗi task kết thúc bằng một commit, không gộp task. Đây là thay đổi **thuần UI**: golden master phải xanh ở mọi bước. Nếu golden đỏ thì dừng lại và điều tra. **Không** chạy `UPDATE_GOLDEN=1`.

**Mục tiêu:** Người chơi dùng được bàn phím cho hai thao tác lặp nhiều nhất:
- **Space / Enter**: sang tuần mới. Phải tương đương **bấm nút `#nextBtn`**, tức là đi qua đúng luồng `nextWeek()` không tham số: cảnh báo sự kiện chờ (`viewSkipWarn`), đề xuất (`viewProps`), xếp lịch (`startPlan`), rồi mới mô phỏng tuần. **Không bao giờ** gọi `nextWeek(true,true)`.
- **Esc**: đóng modal/sheet đang mở (tương đương bấm ✕).

Phím tắt **không** kích hoạt khi: đang gõ trong `input`/`textarea`/`select`/`contenteditable`; có phím bổ trợ Ctrl/Meta/Alt; tutorial đang hiển thị. Riêng Space/Enter còn bị chặn khi sheet đang mở, để người chơi không lỡ tay sang tuần.

**Tiêu chí "xong":**
- [ ] `npm test` xanh, có thêm `tests/unit/keyboard.test.js` (jsdom) phủ mọi điều kiện chặn ở trên.
- [ ] `npm run check:handlers` xanh. Tính năng này không thêm handler inline nào.
- [ ] `npx playwright test` xanh: golden 30 và 110 tuần **giữ nguyên byte**, smoke có thêm kịch bản bàn phím.
- [ ] Không file nào trong `src/systems/`, `src/state.js`, `src/save/` hay `legacy/` bị sửa.

**Kiến trúc:** Thêm một module UI lá mới là `src/ui/keyboard.js`. Module này chỉ dùng DOM, không import system, `state` hay module UI khác. Nó gồm:
- `keyAction(e, doc)`: hàm quyết định, gần như thuần. Trả về `'next' | 'close' | null`.
- `initKeyboard(doc)`: gắn **một** listener `keydown` lên `document` và trả về hàm gỡ listener. Khi có hành động, listener **bấm hộ** phần tử DOM tương ứng: `#nextBtn.click()` cho `'next'` và `#sheet.on .panel > .x` `.click()` cho `'close'`.

`src/main.js` gọi `initKeyboard()` sau `render()`.

**Tech stack:** không thêm gì. Dùng lại Vitest + jsdom (unit) và Playwright (smoke).

### Quyết định thiết kế & lý do

1. **Bấm hộ phần tử DOM (`#nextBtn.click()`, `.x.click()`) thay vì import `nextWeek`/`closeM` rồi gọi trực tiếp.** Yêu cầu là "tương đương bấm nút". Bấm hộ cho ra **cùng một handler inline**, nên nếu sau này nút đổi `onclick` (vd thêm xác nhận), phím tắt tự đi theo. Một panel tương lai mà cố ý không có ✕ (modal bắt buộc) cũng tự được Esc tôn trọng. Thêm nữa `keyboard.js` thành lá UI, không import vòng với `systems/week.js` ↔ `ui/planning.js`.
2. **Một listener `keydown` trên `document`, gắn từ `main.js`**, không dùng `onkeydown` inline. Cách này không chạm `globals.js` và `check:handlers`, và chỉ chạy logic top-level ở `main.js` đúng quy tắc chống TDZ.
3. **Tách `keyAction` (quyết định) khỏi `initKeyboard` (tác dụng)** để unit test từng điều kiện chặn mà không phải dựng cả game.
4. **Nhường phím cho phần tử đang focus.** Với Space/Enter, nếu target là `button, a[href], summary, input, [role=button], [tabindex]` thì không làm gì và để trình duyệt tự kích hoạt. Cách này tránh bị bấm hai lần trên `#nextBtn` và giữ nguyên khả năng dùng Tab + Enter. Đánh đổi xem Câu hỏi mở 2.
5. **Bỏ qua `e.repeat` và `e.isComposing`.** Giữ Space không được tua liên tục qua nhiều tuần. Người gõ tiếng Việt bằng bộ gõ (IME) có thể nhấn Enter để chốt chữ, nên lúc đang soạn chữ thì không được bắt phím.
6. **Chỉ `preventDefault()` khi thực sự có hành động**, để Space vẫn cuộn trang trong những trường hợp phím tắt bị chặn.

## Câu hỏi mở

> Mỗi câu kèm **giả định tạm** mà plan đang dùng. Nếu người duyệt trả lời khác thì chỉ cần sửa `keyAction` và test tương ứng ở Task 1.

> **Đã chốt (người dùng, 2026-10-09):** câu 1 → chặn mọi phím khi tutorial đang hiện. Các câu còn lại đang chờ người dùng duyệt.

1. **Tutorial đang hiển thị: chặn tất cả phím tắt, hay cho Esc = "Bỏ qua" (`tutEnd()`)?**
   *Giả định:* chặn **tất cả**, Esc không làm gì. `tutEnd()` ghi `S.tut=1` rồi `save()`. Tuy không phải gameplay, đây vẫn là thay đổi state mà người dùng chưa yêu cầu.
2. **Khi focus nằm trên một nút khác (vd nút dock vừa click), Space/Enter làm gì?**
   *Giả định:* nhường trình duyệt (kích hoạt nút đang focus) vì a11y và để tránh bấm hai lần. Một phương án khác: bắt phím nếu nút **không** `:focus-visible` (tức được focus bằng chuột), rồi `preventDefault` và sang tuần. Đổi lại phải dựa vào heuristic `:focus-visible`, mà jsdom/nwsapi không hỗ trợ ổn định nên chỉ test được bằng e2e.
3. **Esc khi đang gõ trong ô text của sheet (vd `#codeIn`, `#sTitle`): có đóng sheet không?**
   *Giả định:* **không**, theo đúng chữ của yêu cầu ("không kích hoạt khi đang gõ"). Checkbox/radio không tính là "đang gõ", nên Esc vẫn đóng được sheet khi focus nằm trên checkbox.
4. **Shift có tính là phím bổ trợ không?** Yêu cầu chỉ liệt kê Ctrl/Meta/Alt.
   *Giả định:* **có chặn** Shift. Shift+Space là phím cuộn lên của trình duyệt, và chặn thêm thì ít rủi ro sang tuần nhầm hơn.
5. **Có cần gợi ý phím tắt trong UI không?**
   *Giả định:* thêm `title="Phím tắt: Space / Enter"` và `aria-keyshortcuts="Space Enter"` cho `#nextBtn` trong `index.html`. **Không** sửa nội dung `TUT` hay nhãn nút. Sửa văn bản tutorial thì cần duyệt câu chữ.
6. **Esc có nên đóng `#toast` không?**
   *Giả định:* không. Toast tự ẩn sau 2,2 giây.

2. **Cài đặt** `src/ui/keyboard.js`. Đây là module lá: không import gì từ `systems/`, `state.js`, `save/` hay UI khác, và không chạy logic ở top-level:
   ```js
   /* ---- Phím tắt: Space/Enter = Kết thúc tuần, Esc = đóng sheet ---- */
   const TYPING = 'textarea, select, [contenteditable]:not([contenteditable="false"]), input:not([type=checkbox]):not([type=radio]):not([type=button]):not([type=submit]):not([type=reset]):not([type=range]):not([type=color]):not([type=file])';
   const ACTIVATABLE = 'button, a[href], summary, input, select, textarea, [role="button"], [role="link"], [tabindex]:not([tabindex="-1"]), [contenteditable]:not([contenteditable="false"])';

   export function keyAction(e, doc = document) {
     if (e.defaultPrevented || e.repeat || e.isComposing) return null;
     if (e.ctrlKey || e.metaKey || e.altKey || e.shiftKey) return null;
     const t = e.target && e.target.closest ? e.target : null;
     if (t && t.closest(TYPING)) return null;
     if (doc.getElementById('tut')) return null;
     const sheetOn = !!doc.getElementById('sheet')?.classList.contains('on');
     if (e.key === 'Escape') return sheetOn ? 'close' : null;
     if (e.key === ' ' || e.key === 'Enter') {
       if (sheetOn) return null;
       if (t && t.closest(ACTIVATABLE)) return null; // để trình duyệt tự kích hoạt nút đang focus
       return 'next';
     }
     return null;
   }

   export function initKeyboard(doc = document) {
     const onKey = (e) => {
       const a = keyAction(e, doc);
       const el = a === 'next' ? doc.getElementById('nextBtn')
                : a === 'close' ? doc.querySelector('#sheet.on .panel > .x') : null;
       if (!el || el.disabled) return;
       e.preventDefault();
       el.click(); // cùng handler inline với chuột: nextWeek() / closeM()
     };
     doc.addEventListener('keydown', onKey);
     return () => doc.removeEventListener('keydown', onKey);
   }
   ```
   - Ghi chú DOM/test: hàm chỉ đọc DOM qua `doc`, nên unit test bằng jsdom + `SHELL` (`tests/unit/helpers.js`) được. `SHELL` đã có `#nextBtn` và `#sheet`, nên **không cần sửa helpers**. `#tut` thì tự thêm trong test (`document.body.insertAdjacentHTML('beforeend','<div id="tut"></div>')`).

     await page.keyboard.press('Escape');
     await expect(page.locator('#tut')).toBeVisible();
     await expect(page.locator('#sheet')).not.toHaveClass(/on/);
