# Starlight Ent. — Internationalization (i18n) plan, phase 2

> **For the implementer:** work through the tasks in order. Each task ends with exactly one commit; do not merge tasks. After **every** task:
> - the golden master (`tests/golden/*.json`) is green **without** being updated, for both `vi` and `en`;
> - the Vietnamese display snapshots from task 1 are green **without** `vitest -u`;
> - the sink snapshot from task 1 (every `addLog`/`hist`/`lessons`/`busy`/`pushEv` call) is green without `-u`.
>
> If any of these goes red, stop, find the drift (usually a translated string leaking into `S`, a reflowed template, or an added/removed RNG call), fix it, then continue. Never run `UPDATE_GOLDEN=1` or `vitest -u` against the phase 2 safety nets.

**Goal:** With `en` selected, every piece of UI the player reads is English: every room sheet, modal, card, button, label, `<select>` option, table header, toast, `aria-label`, `title` tooltip, placeholder and empty state. That covers `src/ui/*` and the render functions in `src/systems/*`, including this branch's new features (contests, recruiters, GM, manager domains, the save view, the lessons card on the artist profile). Text **stored in `S`** stays Vietnamese until phase 3: the log, `a.hist`, `a.lessons`, `busy.title`, stored event and proposal reasons, and generated names and titles.

**Done criteria:**
- With `lang=en`, a jsdom render of every room and every view (built from a rich seeded game state) contains no Vietnamese, apart from strings that come from `S`. Toasts from a fixed set of failing actions contain no Vietnamese either. This is proven by `tests/unit/ui-en.test.js`.
- With `lang=vi`, the full HTML of every room and view, and the toast texts, are **byte-identical** to before phase 2. This is proven by file snapshots recorded in task 1.
- `S` is language-independent. A seeded 56-week game that opens rooms and views every week produces the same `JSON.stringify(S)` and the same number of `Math.random` calls with `vi` and `en` (unit test). The e2e goldens pass with both languages.
- `npm run check:i18n` keeps `vi`/`en` key and placeholder parity, and now also fails on duplicate keys across locale parts. `node scripts/i18n-literals.mjs --strict` reports no Vietnamese literal in `src/` outside sinks, kept data tables and the reviewed allowlist.

**Intentional gameplay change:** **No.** This is display-only. No string that reaches `S` changes, no RNG call is added, removed or reordered, and `S` keeps its shape (no migration). The golden stays **unchanged**.

**Architecture:** This builds on phase 1 (`t()`, `money()`, `roomName()`, locale registry, `check:i18n`). Phase 2 adds four things:
1. **Locale parts.** Each locale file merges per-area part files (`locales/vi/*.js`, `locales/en/*.js`), so no dictionary grows to 2,000 lines.
2. **`tVi()`.** A lookup pinned to Vietnamese, for helpers whose output goes both to the screen and into `S`.
3. **`src/i18n/labels.js`.** Display names for the data tables, looked up by id (`statName('vocal')`). The data tables keep their Vietnamese `n` fields because log code still reads them.
4. **Safety nets.** A test harness (`tests/unit/sim.js`) that builds a rich seeded state and renders every surface. It feeds the `vi` byte-identity snapshots, the `S` language-independence test and the `en` leftover-Vietnamese guard. A static literal scanner, `scripts/i18n-literals.mjs`, catches branches the harness never renders.

**Tech stack:** no new dependencies. Vitest `toMatchFileSnapshot` (Vitest 2.1), jsdom, `Intl` only for the save-view date.

## Design decisions & rationale

1. **Data labels: keep the Vietnamese tables and add display lookups by id.**
   - *Option A (phase 1's outline): drop `n` from the tables, as with `ROOMS`.* This has a single source of truth, but about 25 `addLog`/`hist`/`lessons` sites read `CONCEPTS[k].n`, `MSK[k]`, `MDOM[d]`, `BIZ[k].n`, `OFFER[t].n`, `STATS[k]`, `GENRES[g].n` and `DRT[t]`. Every one of them would have to change to `tVi('concept.'+k)`. That touches sinks (the riskiest code), grows the diff, and the sink snapshot could no longer prove "no sink changed".
   - *Option B: make the tables language-aware (getters that call `t()`).* This is wrong: log sites would then write English into `S` when `en` is active, and golden-en would go red.
   - *Option C (chosen): leave the tables as they are and add `src/i18n/labels.js` with `statName(k)`, `trainName(k)`, `conceptName(k)`, `genreName(k)`, `offerName(type)`, `mskName(k)`, `mskDesc(k)`, `domName(d)`, `dayShort(i)`, `dayName(i)`, `bizName(k)`, `relTagName(tag)`. Each is a one-line `t(\`stat.${k}\`)`.* UI code calls the helper and sinks keep reading the table. A parity test asserts, for `vi`, `statName(k) === STATS[k]` for every key (and likewise for each table). That proves the `vi` output is identical and stops the two sources from drifting. Phase 3 converts the log sites and only then drops `n`. `labels.js` imports only `./index.js`, so `i18n/` stays a leaf (no `data/` import; the tests do the cross-check).
2. **Dual-use helpers take `tr = tVi`.**
   - *Option A: two twin functions (`targetName` for logs, `targetNameT` for the UI).* This duplicates logic, and the two drift apart.
   - *Option B: a `tr` parameter that defaults to `t`.* Every existing sink call would silently start writing English under `en`. Golden-en would catch it, but only on the paths the golden exercises.
   - *Option C (chosen): `tr = tVi` default.* Existing call sites (sinks included) are untouched and stay byte-identical, so the sink snapshot proves it. UI call sites pass `t` explicitly. A forgotten `t` leaves Vietnamese on screen, which the `en` guard catches. A wrong `t` in a sink is impossible without editing the sink, which the sink snapshot catches. The cost is one extra argument at UI call sites.
   - `tVi(k, p)` lives in `i18n/index.js`. It shares the replacer with `t` but always reads `DICTS.vi`.
3. **Locale parts per area.** Phase 2 adds about 1,500–2,000 keys. `locales/vi.js` becomes `meta` plus `dict: { ...core, ...shared, ...lobby, … }`, importing `./vi/<area>.js` (each `export default { 'key': … }`), and `en.js` mirrors it. The registry glob `./locales/*.js` and `check-i18n.mjs` (`readdirSync(DIR).filter(f => f.endsWith('.js'))`) only see the top-level files, so neither needs to change. Node's dynamic `import()` resolves the relative part imports, which must use explicit `.js` extensions. A spread silently overwrites duplicate keys, so each locale also exports `parts` (an array of `[name, dict]`), and the check reports keys defined in more than one part. Phase 1 keys move into `vi/core.js` / `en/core.js` unchanged.
4. **Key naming.** Area prefixes, lowerCamel leaves: `common.*` (units, yes/no, week labels), `toast.*` (shared toasts), `stat.*`, `train.*`, `concept.*`, `genre.*`, `offer.*`, `msk.*`, `mskd.*`, `dom.*`, `day.*`, `dayn.*`, `biz.<k>`, `rel.*` (dorm/profile relation tags), then one prefix per area: `lobby.*`, `batch.*`, `comp.*`, `rec.*`, `debut.*`, `mgr.*`, `gm.*`, `art.*` (profile), `pa.*`, `mentor.*`, `dorm.*`, `rep.*` (reports), `plan.*`, `award.*`, `studio.*`, `song.*`, `release.*`, `promo.*`, `acting.*`, `sales.*`, `fin.*`, `hr.*`, `renew.*`, `hs.*`, `market.*`, `invest.*`, `ceo.*`, `eval.*`, `pr.*`, `inv.*`, `meet.*`, `offerCard.*`, `prop.*`, `sec.*`, `ev.*` (`ev.<kind>.t/d/o.<k>`), `mx.*`, `v3.*`, `sx.*`, `save.*`. Plurals and composite counts are **function values** in both languages (phase 1 rule: if `vi` is a function, `en` must be too). Shared unit helpers: `common.weeks` (`p => \`${p.n} tuần\`` / `` `${p.n} week${p.n == 1 ? '' : 's'}` ``), `common.people`, `common.members`, `common.artists`, `common.trainees`, `common.yw` (`'N{y}·T{w}'` / `'Y{y}·W{w}'`).
5. **Byte-identical `vi` by file snapshots of everything rendered, recorded before any change.** Phase 1's snapshot only covers the phase 1 surfaces (titles, dock, tutorial). Task 1 records the **full** `#sheet` HTML of every room and view, the top-bar extras, building badges and toast texts for two seeded states. It uses `toMatchFileSnapshot('__snapshots__/ui-vi/<name>.html')`, one file per surface, so a drift shows as a readable HTML diff. These files are the "display golden" for phase 2 and are never updated during phase 2.
6. **`S` language-independence at unit level, not only e2e.** The e2e goldens never open a room sheet, so render paths that write `S` or call RNG (`viewDebutQ` → `gName`/`dWish`, `viewPA` → `genPAC`, `prHTML` → `data-t`) are invisible to them. `tests/unit/i18n-state.test.js` plays the harness game with a room or view open every week (so `act()` re-renders it), once in `vi` and once in `en`, and asserts equal `JSON.stringify(S)` and an equal `Math.random` call count.
7. **Sink snapshot.** `scripts/lib/js-spans.mjs` extracts the full source text of every sink call: `addLog(`, `recLog(`, `pushEv(`, `.hist.unshift(`, `.lessons.unshift(`, `busy={`, `S.prHist.unshift(`, `prob.push(`. It uses a small scanner aware of strings, template literals and `${}`. `tests/unit/i18n-sinks.test.js` snapshots the sorted `file: span` list, without line numbers. Phase 2 must never change a sink. Any edit inside one turns this test red, before the golden would even notice.
8. **Leftover-Vietnamese guard: render-based plus static, both achievable.**
   - *Render guard (`tests/unit/ui-en.test.js`):* render each surface with `lang=en` from the harness state. Collect `textContent` plus the `title`, `aria-label`, `placeholder` and `label` attributes. **Step 1:** remove, longest first, every string found by walking `S` (deep) that contains a Vietnamese letter. This strips names, titles, log lines, history, lessons and stored reasons that are shown verbatim. **Step 2:** split the rest into words. A word containing a Vietnamese letter (`/[àáảãạăằắẳẵặâầấẩẫậèéẻẽẹêềếểễệìíỉĩịòóỏõọôồốổỗộơờớởỡợùúủũụưừứửữựỳýỷỹỵđ]/i`) passes only if it appears in a **short** `S` string (≤ 40 chars, not under `log`/`hist`/`lessons`/`why`/`prob`/`ev`/`prHist`), which covers sliced names like `x.n.slice(2)`, or in a small `ALLOW_WORDS` set of proper nouns from data. **Step 3:** also flag unaccented Vietnamese tokens that only show up in UI chrome: `/\b(TTS|QL|GĐ|CN|tr)\b/`, `/\bN\d+·T\d+\b/` and `/\bT[2-7]\b/`. The test prints each offender with 40 chars of context. Toasts are captured with a `MutationObserver` on `#toast` while running a `TOAST_CASES` table. Each area task appends its surfaces to `EN_DONE`, so the guard tightens as the work progresses. Task 14 asserts `EN_DONE` covers every registered surface.
   - *Static scanner (`scripts/i18n-literals.mjs`):* the harness cannot reach every branch (rare events, edge-case empty states). The scanner strips comments, sink spans, the kept data/name tables (`KEEP_CONSTS`: `STATS`, `TRAIN`, `MSK`, `MSKD`, `MDOM`, `GENRES`, `CONCEPTS`, `OFFER`, `PLESSON`, `PARTNERS`, `TT`, `RIVALS`, `FN`, `MN`, `LNM`, `MGN`, `GNAMES`, `SONGS`, `SONGW`, `EXTN`, `SCOUT_W`, `COMP`, `DCOMP`, `DAYS`, `DAYN`, `DR`, `DRT`, `BIZ`, …) and `src/i18n/locales/**`. It then lists every remaining string or template-literal fragment containing a Vietnamese letter as `file: fragment`. `scripts/i18n-literal-allow.json` holds reviewed exceptions, each `{ file, text, why }` (e.g. `"stored in S.rivals[].last (phase 3)"`, `"transfer.js Error message kept for tests; e.key is displayed"`). `--report [files…]` prints, and `--strict` exits 1 on unallowlisted findings. It becomes part of `npm run check:i18n` in task 14.
9. **`fmt` → `money` only in display code.** Inside sink spans `fmt` stays, and the sink snapshot enforces it. Literal amounts in UI text become params: `'Tổ chức casting mới (10 tr)'` becomes `t('lobby.recast', { m: money(10e6) })`, with vi value `'Tổ chức casting mới ({m})'`.
10. **Save errors carry a key.** `transfer.js` throws `Object.assign(new Error('Mã không hợp lệ'), { key: 'save.err.invalid' })`. The Vietnamese message is unchanged, so `transfer.test.js` regexes still pass. `saveView` shows `e.key ? t(e.key) : e.message`. `ioMsg` stores `{ k, p }` rather than rendered text, so switching language while the save sheet is open re-renders correctly.
11. **No markup changes.** No new wrappers, attributes, classes or `data-test` hooks. They would change the `vi` HTML. All hooks the tests need come from existing ids, classes and `onclick` selectors.

## Risks

- **Translated text leaking into `S`.** The known paths are the dual-use helpers (decision 2), `prHTML`'s `data-t` (keep `tVi`), `dWish`/`hsRisk`/`shortWhy`/`debutRec().short` (stored, keep vi), `ensureCurBatch` (`n:'Lứa …'` stored), group/batch default names and `genTitle`. These are covered by the unit-level `S` test (decision 6), golden-en and the sink snapshot. When a task finds a new dual-use helper, it uses the `tr = tVi` pattern and adds it to the hand-off list.
- **Render-time RNG.** `gName`, `dWish`, `genPAC` and `renderBuilding` must be called exactly as before. Never "simplify" a template so a helper is called once instead of twice, or the other way round. Example: `debutRec(t)` is called twice in `briefOf`, and both calls stay. The `Math.random` call-count assertion in `i18n-state.test.js` catches this.
- **Template reflow breaks `vi` byte-identity.** Replacing `Đang ở đây (${here.length})` with `${t('room.here',{n:here.length})}` is safe. Moving a newline, collapsing spaces or reordering attributes is not. The file snapshots catch it, and the fix is to restore the original whitespace.
- **Strings used as logic.** `<option value>`, `onclick` arguments, `det()` keys (`S.ui`), `x.n.slice(2)` (emoji prefix of act names), `line(a).replace('<span class="sp"></span>', …)` in `planning.js`, and selectors such as `onclick*="lobby"` must not change. Translate text nodes and display attributes only.
- **Escaping.** Dictionary values are trusted HTML. Names and titles passed as params must be `esc()`-ed by the caller exactly as today, e.g. `t('mgr.boss', { n: esc(m.name) })`. Never pass `mNameH(m)` output through `esc` (it is already HTML). Review every `{name}` param.
- **Snapshot determinism.** The save view prints `new Date(…).toLocaleString()`, so freeze it with `vi.useFakeTimers({ toFake: ['Date'] })`, `vi.setSystemTime(1790000000000)`, and also normalise `/\d{1,2}:\d{2}(:\d{2})?[^<]*\d{4}|\d{1,2}\/\d{1,2}\/\d{4}[^<]*/` to `<date>`. `det()` open states come from `S.ui`, so the harness starts with `S.ui = {}`. Chibi positions are not inside sheets.
- **Runtime of the harness.** 56 weeks in jsdom with rendering takes roughly 10–20 s. Build the state once per test file (`beforeAll`) and `structuredClone` it (via `setState`) before each surface or toast case.
- **English length on mobile.** Long labels in buttons and selects may wrap at 375 px. Task 14's smoke test opens every dock room with `en` at 375×812 and checks `scrollWidth <= 375`. Fix with shorter wording in `en/*.js`, not with CSS.
- **Merge friction.** Tasks 3–13 touch the same big files (`rooms.js`, `ext2.js`, `ext3.js`, `views.js`) but different functions. Work strictly in sequence.
