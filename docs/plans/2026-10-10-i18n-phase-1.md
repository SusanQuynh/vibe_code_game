# Starlight Ent. — Internationalization (i18n) plan, phase 1

> **For the implementer:** work through the tasks in order; each task ends with one commit; do not merge tasks. After **every** task, the golden master (`tests/golden/*.json`) must be green **without** being updated. If the golden goes red, stop, find the drift (usually a string leaking into `S` or a changed number of RNG calls), make it green, then continue. Never run `UPDATE_GOLDEN=1` during this phase.

**Goal:** Add English alongside Vietnamese (the default). Players switch language with a 🌐 button in the top bar; the game re-renders in place, with no reload and no lost state. Phase 1 builds the i18n framework and translates the fixed UI: the top bar (masthead), room names and descriptions (`ROOMS`), the dock, room titles, common buttons and the tutorial. Adding a new language takes just **one dictionary file**.

**Done criteria:**
- With `en` selected, the masthead, the building (room names, NPC labels), the dock, room `<h2>` titles, the ✕ button, "tap again" buttons and the tutorial all show English, with `<html lang="en">`. Switching back to `vi` makes those parts **byte-identical** to before this work (proven by a snapshot test).
- The language choice survives a reload and is not stored in `S`, the save, or the `SL1.` code.
- The 30-week and 110-week goldens are green with both `lang=vi` and `lang=en`.
- `npm run check:i18n` fails when a locale is missing keys, has extra keys, or has mismatched placeholders compared with `vi`.

**Intentional gameplay change:** **No.** This is a display-only change. No string that goes into `S` changes, and no RNG calls are added or removed. The golden stays **unchanged**.

**Architecture:** A small hand-written `src/i18n/` module with `t(key, params)`, `getLang/setLang/initLang`, and a locale registry loaded with `import.meta.glob('./locales/*.js', { eager: true })`. Dictionaries use **flat dotted keys** (`'top.week'`, `'room.ceo.name'`). Values are strings with `{x}` placeholders, or `(p) => string` functions for plurals. `vi.js` is the source of truth. Other locales must have **exactly** the `vi` key set. DOM-touching parts (`applyStatic`, the language picker, re-rendering) live in `src/ui/lang.js`. The chosen language is stored in `localStorage['starlight_lang']`, separate from the save.

**Tech stack:** no new dependencies. Uses `import.meta.glob` (built into Vite and Vitest); `Intl` is optional.

## Design decisions & rationale

1. **Hand-written `t(key, params)` (about 40 lines), no library.**
   - *Option A: i18next or similar.* Plurals, namespaces and lazy loading out of the box. In exchange: a ~40 KB dependency, an API to learn, and mostly unused features. The game has no framework and renders with template strings, so it only needs a lookup function.
   - *Option B: a tiny library (rosetta, ~300 B).* Lightweight, but still a dependency, and it lacks the one thing the project needs most: missing-key checks in CI.
   - *Option C (chosen): write it.* `t` looks up `dict[lang][key] ?? dict.vi[key] ?? key` and replaces `{x}`. If the value is a function, it calls `fn(params)`, which is enough for English plurals. No dependency, small diff, easy to test, and key checking lives in the repo. If more complex plurals are needed, function values can call `Intl.PluralRules` without changing the API.
2. **Flat dotted keys, with `vi.js` as the source of truth.** Flat keys make comparing key sets across locales a matter of `Object.keys`, no recursion. Prefix conventions: `top.*`, `room.<id>.{name,dock,desc}`, `npc.<id>`, `btn.*`, `tut.<stepId>.{t,d}`, `lang.*`, `saved.*`, `fmt.*`.
3. **Registry via `import.meta.glob('./locales/*.js', { eager: true })`.** Each locale file does `export default { meta: { code, name, htmlLang }, dict: {…} }`. To add a language, just drop in `src/i18n/locales/ja.js`. The registry, the picker and the key check pick up the new file automatically. Vitest supports `import.meta.glob`. The Node script `check-i18n.mjs` reads the directory with `fs` and uses dynamic `import()`, so it does not depend on Vite.
4. **Store the language in `localStorage['starlight_lang']`, not in `S`.**

   | | Stored in `S`/save | Separate localStorage key (chosen) |
   |---|---|---|
   | Golden | New field in `S` → snapshot changes → needs `UPDATE_GOLDEN` | No impact |
   | Old saves | Needs a migration in `storage.js` | Not needed |
   | `SL1.` export/import | Language travels with the save, so importing someone else's save switches the UI language (surprising) | Language is the viewer's preference, per device (as it should be) |
   | `resetGame` | Choice is lost | Choice is kept |

   The cost: switching browsers means choosing the language once more. Acceptable.
5. **`i18n/` is a leaf module**, like `core/` and `data/`: it imports no systems or UI. `t()` is pure, does not touch the DOM, and does not call `Math.random`. No logic runs at top level. `initLang()` (which reads localStorage) is only called from `main.js`. Before `initLang` runs the language is `vi`, so existing unit tests are unaffected.
6. **Switching language: a 🌐 button on the masthead opens a `viewLang` modal.** The modal lists every locale in the registry, so it still works with 3–4 languages (a two-state toggle would not scale). `chooseLang(code)` calls `setLang` → `applyStatic(document)` → `render()` → `curView()` if a sheet is open → `tutShow()` if the tutorial is running. That is an in-place re-render. It does **not** call `act()`, since `act` also calls `cleanBatches()` and `save()`, i.e. unnecessary logic.
7. **The static shell in `index.html` uses `data-i18n` / `data-i18n-aria` attributes** instead of moving the whole shell into JS. Small diff, the initial HTML stays Vietnamese so there is no text flash in the default case, and `applyStatic(root)` can be reused for `#saved`.
8. **Money:** `fmt(m, u = FMT_VI)` only gains a default parameter. Every existing call (including those inside `addLog`) produces exactly the same output as before. The UI uses `money(m)` from `i18n` (`fmt(m, t('fmt.units'))`). Phase 1 only uses `money()` for `#money` on the masthead. `fmt` does not switch with the language, because then `S.log` would contain English units when a player picks `en`, making `S` depend on a display preference.
9. **`ROOMS` drops `n`/`s`; the dictionary is the single source.** Keeping `n`/`s` alongside the dictionary would create two sources of truth. Order and `id`/`f`/`ic` are unchanged, so `renderBuilding` iterates identically (RNG unchanged). The dock label becomes a precomputed key `room.<id>.dock`. For `vi`, its value must equal the old `n.replace(/^Phòng /,'')` exactly, as the snapshot test proves.
10. **A Vietnamese UI snapshot as a "display golden".** The golden master only captures `S`, so it cannot catch on-screen text bugs. Task 1 adds Vitest (jsdom) snapshots of the phase 1 surfaces **before** any changes, and later tasks must keep them green with `lang=vi`.
11. **Dictionaries are trusted HTML; callers escape parameters.** This matches the current template-string convention: user data such as artist names must be `esc()`-ed before being passed to `t()`. Some tutorial sentences contain `<b>`, so `t()` does not auto-escape.

## Risks

- **Strings leaking into `S` → red golden.** Phase 1 changes no `addLog`, `title:` or `n:` that is written into `S`. In the "tap again" functions only the `btn.textContent` line changes. Safety net: run the golden with `lang=en` (task 4). If any language-dependent string reaches `S`, that test goes red immediately.
- **RNG in `renderBuilding`.** Dropping `n`/`s` from `ROOMS` while accidentally reordering or filtering rooms would change the number of `R()` calls and turn the golden red. No `render()` is added at boot: `initLang()` and `applyStatic()` only touch the static DOM. `chooseLang` does call `render()`, but only when the player clicks, which the golden never does. Also, `pos` is already populated, so re-rendering makes no extra `R()` calls.
- **TDZ / circular imports.** `TUT` is currently a top-level constant holding strings. Writing `TUT=[{t:t('…')}]` at top level would call `t` before `initLang` and freeze the load-time text. So `TUT` keeps only `id`/`sel`/`first`, and the text is looked up in `tutShow()`. General rule: never call `t()` at top level.
- **Layout with English.** English text is longer and may overflow the dock or masthead at 375px. The smoke e2e (task 8) checks for no horizontal scroll with `lang=en`. If it breaks, write shorter `room.<id>.dock` values rather than changing CSS.
- **Brittle UI snapshots.** Only capture the phase 1 surfaces (sheet `h2`, masthead, dock, room labels, tutorial). Do not capture room contents, since phase 2 will change them.
- **Dynamic keys can't be scanned.** `t(\`room.${id}.name\`)` is not caught by a regex. Tests iterate over `ROOMS`, `NPC` and `TUT` to check that the keys exist.
- **XSS.** Parameters are not escaped automatically. Review every place that passes a name into `t()`. Phase 1 passes almost no user data (only counts).
- **jsdom and `localStorage`.** The `beforeEach` in `game.test.js` calls `localStorage.clear()`, which also removes the language key. i18n tests must call `setLang('vi')` in `afterEach` so module state does not leak into other tests.

### Task 2: i18n framework + missing-key check

**Files:** create `src/i18n/index.js`, `src/i18n/check.js`, `src/i18n/locales/vi.js`, `src/i18n/locales/en.js`, `scripts/check-i18n.mjs`, `tests/unit/i18n.test.js`. Edit `package.json` (add the script `"check:i18n": "node scripts/check-i18n.mjs"`).

1. Write the tests first (`tests/unit/i18n.test.js`, jsdom environment):
   - `t('x.missing')` returns `'x.missing'`.
   - Placeholder replacement: `t('lang.current', { name: 'X' }) === 'Đang dùng: X'`. A placeholder missing from `params` stays as `{name}`.
   - Fallback: a key present in `vi` but missing from the current locale returns the `vi` value. Test it by injecting fake dictionaries via `__setDicts` (exported for tests only).
   - Function values: `t(k, { n: 1 })` calls the function.
   - `setLang('xx')` (nonexistent) is ignored and returns `false`. `setLang('en')` writes `localStorage['starlight_lang']` = `'en'`, and `getLang() === 'en'`.
   - `initLang()`: no key → `vi`. Key `en` → `en`. Junk key → `vi`.
   - `t`, `setLang`, `initLang` **do not call `Math.random`**: spy with `vi.spyOn(Math, 'random')` and check `not.toHaveBeenCalled()`.
   - Parity: for every locale in `langs()`, `diffLocales(vi.dict, L.dict)` returns empty `missing`, `extra` and `badParams`.
   - `afterEach(() => setLang('vi'))`.
2. `src/i18n/index.js` (leaf, no UI or system imports):
   ```js
   const mods = import.meta.glob('./locales/*.js', { eager: true });
   let DICTS = Object.fromEntries(Object.values(mods).map(m => [m.default.meta.code, m.default]));
   export const LANG_KEY = 'starlight_lang';
   let cur = 'vi';
   export const getLang = () => cur;
   export const langs = () => Object.values(DICTS).map(d => d.meta);   // vi first
   export function setLang(c) { if (!DICTS[c]) return false; cur = c; try { localStorage.setItem(LANG_KEY, c); } catch {} return true; }
   export function initLang() { let c = null; try { c = localStorage.getItem(LANG_KEY); } catch {} cur = DICTS[c] ? c : 'vi'; return cur; }
   export function t(k, p) { const v = DICTS[cur]?.dict[k] ?? DICTS.vi.dict[k]; if (v == null) return k;
     return typeof v === 'function' ? v(p || {}) : p ? v.replace(/\{(\w+)\}/g, (m, n) => (n in p ? p[n] : m)) : v; }
   export const __setDicts = d => { DICTS = d; };   // tests only
   ```
   `setLang` does **not** touch the DOM. Setting `<html lang>` happens in `ui/lang.js`.
3. `src/i18n/check.js`: `diffLocales(base, other)` returns the missing keys, the extra keys, and the keys whose `{x}` sets differ. For function values, compare `typeof` on both sides (if `vi` is a function, the other must be too, and vice versa).
4. `vi.js` / `en.js` start with only `lang.title` (`'Ngôn ngữ'` / `'Language'`) and `lang.current`.
5. `scripts/check-i18n.mjs`, in the spirit of `check-handlers.mjs`:
   - `fs.readdirSync('src/i18n/locales')` → `import()` each file → compare against `vi` with `diffLocales`.
   - Scan `src/**/*.js` and `index.html` for `\bt\(\s*'([\w.]+)'` and `data-i18n(?:-aria)?="([\w.]+)"`. Report any key missing from `vi`.
   - On errors, `process.exit(1)`. Otherwise print `OK: N keys × M languages`.
   - Intentional red check: temporarily delete a key from `en.js` → the script must fail → revert.
6. CHECK. The golden is unaffected because nothing imports `i18n` yet.
7. Commit: `feat(i18n): hand-written t()/setLang, locale registry and check:i18n`
